# 프런트엔드 코딩 규칙

## Vue SFC와 컴포넌트

- 새 `.vue` 파일은 `<template>`, `<script setup lang="ts">`, 필요한 경우 `<style scoped>` 순서를 사용한다.
- props와 화면 데이터에는 구체적인 TypeScript 타입을 둔다. `any`로 응답 계약을 감추지 않는다.
- 페이지에 반복되는 독립 UI가 생기면 `app/components`로 분리하되, 한 번만 쓰이는 짧은 표현을 성급하게 추상화하지 않는다.
- 브라우저 전용 API는 SSR 실행 경로에서 직접 접근하지 않는다.

## 클래스와 스타일

- 클래스 단어 구분은 하이픈, 블록과 요소 구분은 단일 언더스코어를 사용한다.
- `__`, `--` 형태의 BEM 구분자는 사용하지 않는다.
- 주변 페이지의 폭, 간격, 색상, breakpoint를 우선 재사용한다. 전역 스타일 변경은 앱 전체 영향이 요청에 포함될 때만 수행한다.
- hover만으로 상태를 전달하지 말고 focus-visible과 작은 화면에서의 동작도 고려한다.

## 상태와 데이터 흐름

- 파생 값은 원본 상태를 중복 복사하기보다 `computed`로 표현한다.
- 비동기 작업은 `try/catch/finally`로 loading 상태가 남지 않게 하고, 사용자 취소·연속 요청 시 오래된 응답이 화면을 덮지 않는지 검토한다.
- 오류와 빈 결과는 의미가 다르면 별도 상태로 표시한다.
- route param은 `string | string[] | undefined` 가능성을 고려해 정규화한 뒤 조회한다.

## 접근성과 내비게이션

- 경로 이동은 `NuxtLink` 또는 `navigateTo`, 동작은 `button`을 우선 사용한다.
- 아이콘만 있는 컨트롤은 접근 가능한 이름을 제공한다.
- 폼 입력에는 label을 연결하고 오류 메시지는 해당 입력과 연관시킨다.
- 키보드로 수행할 수 없는 click-only 상호작용을 새로 만들지 않는다.

## API 소비

- composable의 공개 반환값은 `loading`, `error`, 데이터/동작의 의미가 호출부에서 분명하게 유지되도록 한다.
- `$fetch` 제네릭 또는 명시적 인터페이스로 내부 API 응답을 타입화한다.
- 서버 오류의 민감한 원문을 화면에 그대로 노출하지 않는다.
