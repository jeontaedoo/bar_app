# 외부 데이터 제공자 연동 및 진단

동작을 변경하기 전에 관련 `server/api` 경로, `app/composables` 함수, 이를 사용하는 페이지를 확인한다. 화면 또는 composable도 수정하면 `bar-frontend` 스킬을 함께 적용한다.

- 제공자의 현재 엔드포인트, 응답 구조, 인증 방식, 가용성, 이용 조건을 확인한다. 제공자 장애와 앱 내부 경로·데이터 변환·권한 문제를 구분한다.
- 제공자 요청과 비밀키는 서버에 둔다. 내부 `/api` 경로에는 화면에 필요한 필드만 제공하고, composable은 이 내부 경로를 호출하게 한다.
- 제공자가 실제로 주는 데이터만 변환한다. 없는 선택 필드는 명시적으로 처리하고, 추정한 값을 확인된 사실처럼 표시하지 않는다.
- 상황에 맞는 상태 코드와 메시지를 반환한다. 모든 외부 오류를 404로 바꾸거나 비밀키·원본 오류를 클라이언트에 노출하지 않는다.
- 이용 조건상 앱 연동이나 재배포가 금지되어 있다면 경로를 비활성으로 두거나 데이터 가져오기를 중단하고 필요한 허락을 설명한다. 제공자의 제한을 우회하지 않는다.
- 입력값은 서버에서 검증하고 제공자 timeout, 비정상 응답과 네트워크 실패를 앱 오류와 구분한다. 운영 로그에도 비밀키와 민감한 원문을 남기지 않는다.
- `npm run build`를 실행하고, 가능하면 영향받는 내부 API와 페이지를 직접 요청해 확인한다. 실제로 검증한 범위를 보고한다.
